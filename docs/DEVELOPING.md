# Development · stable Factorio 2.0

## Requirements and layout

Python 3.11+ builds the package. Development tests use `requirements-dev.txt` (Lupa's Lua 5.2 runtime, pytest and Pillow). The game requires Space Age, Quality and Elevated Rails. **2.0.77 is the pinned engine/data target; no experimental build is produced.**

```text
second-nature/
  info.json, settings.lua, data*.lua, control.lua
  shared/                 canonical catalog, constants and pure model
  prototypes/             items, entities, recipes, research, UI and campaign setup
  scripts/
    state.lua             schema, registry, planet properties and copied reports
    upgrades.lua          per-force bounded research multiplier cache
    artwork.lua           persistent lander/status render objects
    machines.lua          completed-craft accounting and physical pollution changes
    campaign.lua          fresh-game desolation, shared lander and arrivals
    pollution.lua         generated-chunk index, total/hotspot survey and local overlay
    natives.lua           confirmed policy, mobile-entity queue and future enforcement
    resistance.lua        productive-clean targets, warnings, groups and smog retreat
    terrain.lua           protected local gardens and bounded Nauvis succession
    telemetry.lua         eleven first-section combinator signals
    network.lua           force-specific ten-minute victory hold
    gui.lua               namespaced dashboard, field guide and confirmation UI
  graphics/               original icons, friendly fauna, gardens and menu illustration
  locale/en/              generated English locale
  README.md, changelog.txt, LICENSE
```

Mutable runtime state belongs in `storage.second_nature`. Module upvalues are functions/constants. **Resolve every `require` during control parsing**; Factorio rejects imports from event callbacks, even when an offline Lua runtime permits them. `control.lua` explicitly imports the core `util` library to initialize runtime deep-copy support.

## Offline validation

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
mkdir -p .cache
git clone --depth 1 --branch 2.0.77 https://github.com/wube/factorio-data.git .cache/factorio-data-2.0.77
.venv/bin/python -m pytest -q
```

The pinned Wube commit is `ce6741a54c3199caad4ed147e9987fd8d5653fdf`. `FACTORIO_DATA_20` can point to that checkout elsewhere. Source-data tests deliberately skip when the checkout is absent; a green partial test suite without it is **not** the full validation run.

The data harness executes official data stages with mock engine enums and explicit stubs for proprietary sprite/ambient/menu payloads. It does not perform C++ validation. Runtime doubles enforce reserved GUI names, crafting-only recipe access and event-time import restrictions, but do not reproduce the full engine.

Edit locale prose in `tools/generate_locale.py` / `tools/campaign_locale.py`, not the generated CFG. Catalog-derived names come from `shared/catalog.lua`. The main-menu JPEG is a separately authored AI-assisted illustration, not regenerated by the icon tool.

### Original industrial/player art

```sh
.venv/bin/pip install -r requirements-art.txt
.venv/bin/python tools/generate_industrial_assets.py
.venv/bin/python tools/generate_expedition_cards.py
```

The optional CPU renderer uses authored mesh primitives, depth-buffered polygon rasterization, directional light and Pillow antialiasing. It needs no Blender/GPU or external models. Generated sheets and `shared/art.lua`/`docs/art/sprite-manifest.json` are committed; tests and packaging do not install NumPy or regenerate them. Run the industrial tools **after** the older general icon generator so new machine/card icons remain consistent.

`--only <names...>` renders selected models for iteration; run the full export before committing a new global manifest. The model/contact sheet and small animation preview are source-art inspection aids, **not in-game screenshots/footage**. Keep sprite sheets within the engine texture limit; pole picture directions must match wire-position count, and character armed locomotion needs exactly 18 or 40 variants.

The basic buildings have four directional eight-frame working sets; turrets have 64 directions and four firing frames. The character has three armor looks, eight-facing idle/tool/running sets and eighteen armed locomotion variants. Review actual aiming/body orientation and fluid/wire alignment in a client—successful headless schema loading does not certify their appearance.
 Preserve it when updating procedural art.

`tests/gui_reserved.lua` records stable LuaGuiElement member names from the 2.0.75 API declarations (the available near-stable typed API). The production rule is stronger: every named child uses `sn_`, so new engine members do not collide with generic child names.

## Actual stable-engine checks

`validate.yml` runs the offline suite **and a required headless engine job** on pushes, pull requests and release validation. The runner downloads the official 2.0.77 headless build; no Factorio account or game binary is stored in Git.

To run locally with a downloaded binary:

```sh
python3 tools/headless.py --factorio /path/to/factorio/bin/x64/factorio
```

The standard-library harness:

1. Detects and rejects non-2.0 engines; builds the current mod version dynamically.
2. Creates isolated mod/write-data directories below `.cache/engine-2.0.77/`.
3. Packages the production mod plus a **test-only** companion mod.
4. Runs the real `--create` path, saves the result, reloads it and benchmarks 2,100 ticks.
5. Requires **both** `SECOND_NATURE_ENGINE_CAMPAIGN_PROBES_OK` and `SECOND_NATURE_ENGINE_SMOKE_OK`, as well as zero process exit status.

The companion creates all five actual planetary surfaces, instantiates every production/monitor prototype and exercises a powered supplied craft, an idle powered machine and an unpowered supplied machine. It checks real counters, pollution, telemetry, lander cargo capacity and friendly-entity/rendering construction.

For campaign APIs, unmodified copies of the runtime modules execute in the companion mod's **isolated storage** against real engine entities/surfaces. These probes cover the generated-chunk survey, desolate generation, permanently protected lander placement/cargo/idempotence, all defense tiers and ammunition, a created character accepting new equipment, wood-free recipe contracts, native conversion/eradication/diplomacy and native attack/retreat commandables. Fixture clocks/state are deliberately arranged to reach the test conditions; this is **not** a natural campaign playthrough. The rocket handler uses an entity-API fixture, not an actual rocket flight.

**A headless save has no interactive player GUI.** These checks do not certify dashboard appearance, arrival camera behavior, menu rendering, player clicks, full logistics balance or multiplayer. See [VERIFICATION.md](VERIFICATION.md) for evidence and outstanding checks.

The sandbox may not reach binary/CDN/log-archive hosts even when GitHub runners can. The harness emits the final engine error as a GitHub check annotation, so failures remain inspectable through `gh api .../check-runs/{id}/annotations`. Do not infer a pass from successful data loading if a runtime callback failed afterward.

## Package

```sh
python3 tools/package.py
# Equivalent:
python3 tools/package.py --target 2.0
```

Output: `artifacts/factorio-2.0/second-nature_0.3.0.zip` and its `.zip.sha256` sidecar. The canonical mod folder sits directly at the archive root. Deterministic ordering, timestamps, permissions, allowlisted source paths and metadata are tested. `--target 2.1` is rejected.

Do not commit `.cache`, virtual environments, game binaries, saves, generated release artifacts or ZIP files. They are ignored, and large engine assets are external to the source repository.

## GitHub publishing

The source workflow uses release tag **`v<mod-version>-factorio-2.0`**. `publish.yml` runs the required validator, packages the **tagged commit**, uploads the canonical ZIP/checksum and re-downloads both for byte comparison and SHA-256 verification.

Example after validation (substitute the actual intended commit):

```sh
gh release create v0.3.0-factorio-2.0 --target <validated-commit> --prerelease \
  --title 'Second Nature 0.3.0 · Ironbound Expedition · stable 2.0' --notes-file release-notes.md
```

Create the release without directly uploading from the sandbox if binary uploads are blocked; the hosted publisher handles them. The repository is private, so download links require authenticated repository access. Never request credentials in chat or embed them in files.

## Regression priorities

- All GUI entry points, reserved names, cleanup and confirmation cancellation.
- Existing saves: no new cargo, sterilization or ecological-value reset.
- Craft counts, recipe switching, pre-removal flushes, powered/idle/frozen/output-blocked behavior.
- Pollutant-free custom surfaces: no forbidden pollution API calls.
- `get_chunks()` includes ungenerated/pollution-only chunks: filter before indexing or terrain access.
- Chunk deletion never regenerates land or restarts a large survey repeatedly.
- Real local/generative smog versus scored toxicity; global and local readings must not be conflated.
- Peaceful mode/diplomacy; no dirty target selection or Gleba sedation.
- Native queue migration, mobile creatures, expansion/spawning, force merges and protected species/planets.
- Infrastructure/ore/paving/support safety; no instant infinite-map pass.
- Force-local beacon progress and continuous readiness requirements.

## Slow ecology test contract

`shared/succession.lua` is a pure time integrator. Test short intervals, hours of growth, prolonged pollution, bounded research, save-copy/replay and large timestamp gaps. Rendering is a separate bounded pass. Habitat condition must continue to simulate with visuals disabled, and only tracked mod-grown/dead trees may be replaced. The new final Nauvis habitat requirement is explicit; do not weaken it to make a short headless fixture look like a natural playthrough.
